# 테스트 통과와 테스트 실행은 다르다

> 2026-09-15

## 배운 것

빌드가 초록이어도 필요한 테스트가 실제로 실행됐다는 뜻은 아니다. DB나 Docker 같은 실행 조건이 없으면 일부 통합 테스트가 `skipped`되고, 나머지 테스트만 통과한 채 전체 빌드가 성공할 수 있다.

테스트 결과를 볼 때는 성공 여부와 함께 숫자를 확인해야 한다.

- 전체 테스트 수
- 실패와 오류 수
- `skipped` 수
- 테스트가 사용한 DB, 프로필과 외부 의존성

검증 범위도 층별로 구분한다.

| 검증 | 확인할 수 있는 것 |
| --- | --- |
| 단위 테스트 | 한 클래스나 함수의 로직 |
| Mock 기반 테스트 | 정해 둔 협력 객체와의 계약 |
| DB 통합 테스트 | 실제 스키마, 제약조건과 트랜잭션 |
| 실제 소켓 테스트 | 네트워크와 보안 필터를 포함한 요청 흐름 |
| 운영 확인 | 배포 설정과 외부 서비스까지 포함한 실제 동작 |

아래 단계가 통과해도 위 단계까지 자동으로 증명되지는 않는다.

## 막혔던 것 / 해결

로컬 빌드는 성공했지만 PostgreSQL 실행 조건이 없어 DB 통합 테스트가 건너뛰어진 적이 있었다. CI 결과에서 `skipped 0`을 확인한 뒤에야 해당 테스트가 실제 DB를 사용해 실행됐다고 말할 수 있었다.

이후에는 `BUILD SUCCESSFUL`만 기록하지 않고 `tests / failures / errors / skipped`와 실행 환경을 함께 남긴다. CI 통과도 외부 API나 운영 배포까지 확인한 것으로 표현하지 않는다.
